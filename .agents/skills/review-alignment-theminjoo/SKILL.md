# review-alignment-theminjoo

더불어민주당 강령·당헌·당규·윤리규범을 NotebookLM 노트북으로 질의해, 실무 문서와 정보 질의를 검토하는 스킬이다. 사용자가 당 소속원이 아닐 수 있으므로, 노트북 응답을 공유할 때는 **당원 관점**과 **중립 관점**을 함께 제시해 사용자가 비교로 이해하게 한다.

## 불변 규칙

- 근거는 NotebookLM 노트북 응답을 우선한다. 임의 추정으로 보완하지 않는다.
- 대상 노트북은 `notebooks/shared-notebooks.json`의 **더불어민주당 강령·당헌·당규·윤리규범** 노트북을 우선한다.
  - notebook_id: `83efdcd0-6ac6-4f25-81fc-f9ae4f4f2276`
- 질의 전 `notebook_get`으로 노트북 접근 가능성을 검증한다. 검증 실패 시 정확한 실패 원인만 보고하고, 로컬 문서 fallback은 사용자가 명시적으로 요청할 때만 사용한다.
- NotebookLM 응답을 공유할 때는 **당원 관점**과 **중립 관점**을 분리해 표기한다. 한쪽만 제시하지 않는다.
- Facts(인용된 1차 근거)와 Interpretation(해석)을 분리한다. 모든 Facts 항목은 출처를 단다.
- 인증·조회 절차는 [setup-notebooklm-mcp](../setup-notebooklm-mcp/SKILL.md)를 따른다.

## 언제 쓰는가

- 정책 제안서가 당의 가치축·규정과 맞는지 검토할 때
- 보도자료, 논평, 공개성명, 메시지 초안의 톤과 표현 리스크를 점검할 때
- 보고서·회의록에서 당의 공식 입장과 개인 발언을 분리할 때
- 당규·윤리규범 조항을 사실 그대로 확인해야 할 때(정보 중심 질의)
- 초안 수정 전에 어떤 문장이 문제인지 먼저 진단할 때

## 절차

### 1. 응답 구조 설계 (선행)

본 검토를 시작하기 전에, 사용자 프롬프트와 세션 전체 맥락을 읽고 응답 구조를 먼저 정한다.

- 입력 유형을 구분한다: 문서 검토 / 메시지 점검 / 정보 사실 확인.
- 사용자가 당 소속원으로 보이는지, 중립적 정보 요청인지 추정 단서를 확인한다(소속을 단정하지 않는다).
- 아래 3개 프로필 중 하나를 선택하고, 선택 근거를 한 줄로 명시한다.

| 프로필 | 선택 신호 | 응답 중심 |
| --- | --- | --- |
| `균형형` | 가치 정합성·찬반 판단이 핵심 | 당원 관점 + 중립 관점 병렬 비교 |
| `정보검증형` | 조항·사실의 정확성이 핵심 | Information / Evidence / Reference / Rationale 분리 |
| `메시지작성형` | 공개 발신용 표현·톤이 핵심 | 표현 리스크 + 대체 문구 + 규정 점검 |

명시적 `profile` 인자가 있으면 그것을 우선한다. 모호하면 `균형형`을 기본값으로 한다.

### 2. 근거 수집 (NotebookLM)

1. 사용자 요청을 명확한 단문 질의로 재기술한다.
2. `notebook_get`으로 대상 노트북 접근을 검증하고, `notebook_describe`로 관련성을 확인한다.
3. `notebook_query`로 질의해 응답과 인용(`sources_used`)을 수집한다.
4. 응답되지 않은 부분만 `근거 부족` 또는 `검증 미흡`으로 표시한다.

### 3. 매핑과 분리

- 문서에서 핵심 주장·요구·약속·표현·이해관계자 언급을 뽑는다.
- 각 항목을 가치 기준과 윤리 기준으로 따로 매핑한다.
  - 가치 기준: 공정, 생명, 포용, 번영, 평화, 노동존중, 민주주의, 자치분권, 성평등, 기후, 복지, 교육, 언론 자유
  - 윤리 기준: 청렴, 성실, 공정한 직무수행, 이해충돌 회피, 금품수수 금지, 자료유출 금지, 성희롱·성폭력 금지, 품위유지
- 부합하는 지점과 충돌하는 지점을 둘 다 적는다. 한쪽만 쓰지 않는다.
- 회의록은 발언자 개인 의견, 당 공식 가치, 절차 맥락을 분리한다.

### 4. 이중 관점 정리

같은 쟁점에 대해 아래 두 관점을 나란히 적는다.

- **당원 관점**: 당 강령·규정 기준에서 이 항목이 어떻게 읽히는지(NotebookLM 응답 근거).
- **중립 관점**: 당적과 무관한 사실·절차·일반 기준에서 어떻게 읽히는지.

두 관점이 갈리면 갈리는 지점을 그대로 드러낸다. 한쪽으로 봉합하지 않는다.

### 5. 중립화 (정보검증형에서 강제)

- `정보검증형` 프로필이면 최종 출력 전에 [neutralize-report-language](../neutralize-report-language/SKILL.md) 기준으로 평가형·추정형 표현을 사실 서술형으로 정리하고 information / evidence / reference 연결을 분리한다.
- 다른 프로필에서는 선택 적용한다. 단 Facts/Interpretation 분리는 모든 프로필에서 유지한다.

### 6. 수정 제안

- 수정이 필요하면 원문을 전면 재작성하지 말고, 문제 문장의 방향만 짚고 대체 문구를 짧게 제시한다.

## 출력 형식

프로필에 맞는 템플릿을 [review-template](./references/review-template.md)에서 선택해 따른다.

## 문서별 판단 포인트

- 정책 제안: 권리 보장, 실행 가능성, 사회적 약자 영향, 지역 형평, 재원 근거를 함께 본다.
- 보도자료/공개성명: 사실 근거, 공격 수위, 혐오·모욕 표현, 민주주의 가치와의 연결을 본다.
- 보고서: 데이터 출처, 해석 과장, 이해충돌 가능성, 내부자료 노출 위험을 본다.
- 회의록: 회의 참여자의 수사와 당의 공식 노선을 자동으로 동일시하지 않는다.

## 금지

- NotebookLM이 검증하지 않은 당 강령·규정 문구를 임의 생성하는 행위
- 당원 관점만 또는 중립 관점만 제시해 한쪽 시각으로 결론을 봉합하는 행위
- 인용 없이 NotebookLM 응답을 일반 지식처럼 재포장하는 행위
- 상대 정당을 풍자하거나 조롱하는 비교표 작성
- 법률 검토가 필요한 사안을 단순 정치 판단으로 처리하는 행위
- 루머, 기사 제목, 2차 요약문만으로 입장을 확정하는 행위

## 결과 기준

- `높음`: 핵심 가치축과 윤리 기준에 대체로 부합하고 큰 적색 신호가 없음
- `중간`: 큰 충돌은 없지만 누락된 가치축 또는 윤리상 애매한 표현이 있음
- `낮음`: 핵심 가치와 직접 충돌하거나 윤리규범상 위험 신호가 반복됨
